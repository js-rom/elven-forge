# Step 5 — Use Case Briefs

## Inputs
- `Use Case Model` from step 4.
- Active schema instruction for use cases and the use case brief template.
- Glossary terms already known.

## Output contract
- One brief per use case, written one at a time and refined with the user before the next.
- Each brief follows the template and states the actor, the goal and a short text story of the interaction.
- Names stay identical to the Use Case Model.

## Preconditions
- `OK 4` approved.
- The use case list is stable.

## Rubric
- Every use case in scope has a brief.
- The brief is a story, not a fully dressed scenario list.
- New domain terms are proposed for the Glossary.

## Evidence required
- Progress list: briefs written vs pending.
- `OK 5` request before persisting anything.

## Anti-patterns
- Writing fully dressed use cases in this step.
- Producing all briefs in one message without review.
- Renaming use cases between steps.
